    10. Die Anwendung [SimuPaie] – Version 6 – Client ASP.NET eines Webdienstes

    10.1. Die Architektur der Anwendung

    Wir entwickeln die Client-Server-Architektur des Tests NUnit wie folgt weiter:

    In [1] wird der Test NUnit durch die Webanwendung der Version 8 ersetzt. Dabei ist zu beachten, dass diese Architektur zwei nicht dargestellte Webserver umfasst:

    • einen Webserver, auf dem der Webdienst [S] ausgeführt wird. Dieser läuft in einer ersten Instanz von Visual Web Developer.
    • ein Webserver, auf dem der Webclient [1] ausgeführt wird. Dieser wird in einer zweiten Instanz von Visual Web Developer ausgeführt.

    Um diese Fehler zu verstehen und zu beheben, muss man sich die Architektur des im Aufbau befindlichen Webprojekts noch einmal ansehen:

    Das Projekt [pam-v6-client-webservice] entspricht der Schicht [web] [1] im obigen Schema. Man sieht, dass diese Schicht mit dem Webservice-Client [C] kommuniziert, einem Client, den wir in Kürze generieren werden.

    • Die Fehler 2, 5 und 7 sind darauf zurückzuführen, dass der Code von [pam-v4] auf DLL der Schicht [metier] verwies, DLL, die sich nun auf der Serverseite und nicht mehr auf der Clientseite befindet.
    • Die Fehler 1 und 3 haben dieselbe Ursache, betreffen diesmal jedoch die DLL der Schicht [dao]
    • Fehler 4 rührt daher, dass der Code von [Global.asax] Spring verwendet und unser Projekt nicht auf die Spring-Klasse DLL verweist. Wir werden diesen Verweis hinzufügen.
    • Fehler 6 rührt daher, dass die Klasse [Employe] in der Schicht [dao] definiert ist, die auf der Client-Seite nicht existiert.

    Die Namespace-Fehler 1, 2, 4, 5, 6 und 7 werden durch die Generierung des C-Clients für den Webdienst behoben. Fehler 3 wird behoben, indem dem Projekt ein Verweis auf die Spring-Klasse „DLL“ hinzugefügt wird. Wir können wie folgt vorgehen:

    • in [1] fügen wir einen Verweis auf das Projekt [pam-v6-client-webservice] hinzu
    • in [4] wurde ein Verweis auf DLL und [Spring.Core] aus dem Ordner [lib] hinzugefügt.

    Nach dem Hinzufügen dieses Verweises in Spring weist die Projektgenerierung einen Fehler weniger auf. Alle anderen Fehler sind auf Codezeilen zurückzuführen, die auf Objekte der Schichten [metier] und [dao] verweisen, die sich nun auf dem Server befinden. Wir werden sehen, dass diese fehlenden Objekte im Webservice-Client [C] generiert werden.

    Betrachten wir die von einem dieser Objekte bereitgestellten Methoden und Eigenschaften:

    • In [1] wird die lokale Klasse [Employe] ausgewählt
    • in [2] finden wir die Eigenschaften der entfernten Entität [Employe] sowie private Felder, die für die eigenen Zwecke der lokalen Entität verwendet werden.

    Sehen wir uns den Code von [Global.asax.cs] an, der Fehler enthält:

    • In den Zeilen 3 und 4 werden Namespaces verwendet, die auf dem Server, aber nicht auf dem Client vorhanden sind.
    • In Zeile 13 wird eine Klasse „[Employe]“ verwendet, für die der richtige Namespace nicht deklariert wurde.
    • In Zeile 14 wird eine Schnittstelle „IPamMetier“ verwendet, die auf dem Client unbekannt ist.

    Ähnliche Probleme sind uns bereits in dem zuvor untersuchten C#-Client begegnet.

    In der Architektur:

    • wird die lokale Schicht [metier] durch den Client [C] vom Typ pam_v6.WsPam.Service1SoapClient implementiert, der die Schnittstelle IPamMetier nicht implementiert, obwohl er ansonsten Methoden mit denselben Namen aufweist.
    • Die bearbeiteten Entitäten (Employe, Indemnites, Cotisations) durch den generierten Client [C] befinden sich im Namensraum pam_v6.WsPam

    Der Code von [Global.asax.cs] entwickelt sich wie folgt:

    
using System;
using System.Collections.Generic;
using Pam.Web;
using Spring.Context.Support;
using pam_v6.WsPam;

namespace pam_v6
{
  public class Global : System.Web.HttpApplication
  {
    // --- statische Anwendungsdaten ---
    public static Employe[] Employes;
    public static Service1SoapClient PamMetier = null;
    public static string Msg;
    public static bool Erreur = false;

    // Start der Anwendung
    public void Application_Start(object sender, EventArgs e)
    {
      // Auswertung der Konfigurationsdatei
      try
      {
        // Instanziierung der Schicht [metier]
        PamMetier = ContextRegistry.GetContext().GetObject("pammetier") as Service1SoapClient;
        // vereinfachte Mitarbeiterliste
        Employes = PamMetier.GetAllIdentitesEmployes();
        // Es ist gelungen
        Msg = "Base chargée...";
      }
      catch (Exception ex)
      {
        // Fehler wird vermerkt
        Msg = string.Format("L'erreur suivante s'est produite lors de l'accès à la base de données : {0}", ex);
        Erreur = true;
      }
    }

    public void Session_Start(object sender, EventArgs e)
    {
      // Es wird eine leere Simulationsliste in die Sitzung eingefügt 
      List<Simulation> simulations = new List<Simulation>();
      Session["simulations"] = simulations;
    }
  }
}
