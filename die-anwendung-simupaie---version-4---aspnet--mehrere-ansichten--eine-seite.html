    8. Die Anwendung [SimuPaie] – Version 4 – ASP.NET / mehrere Ansichten / eine Seite

    Empfohlene Lektüre: Referenz [1], Entwicklung WEB mit ASP.NET 1.1, Abschnitte:

    • Serverkomponenten und Anwendungssteuerung

    • Anwendungsbeispiele MVC mit Serverkomponenten ASP

    Wir betrachten nun eine abgeleitete Version der zuvor untersuchten dreischichtigen Anwendung ASP.NET, die um neue Funktionen erweitert wurde. Die Architektur unserer Anwendung entwickelt sich wie folgt:

    Die Bearbeitung einer Anfrage eines Kunden erfolgt in folgenden Schritten:

    1. Der Kunde sendet eine Anfrage an die Anwendung.
    2. Die Anwendung verarbeitet diese Anfrage. Dazu benötigt sie möglicherweise die Unterstützung der Schicht [métier], die ihrerseits die Schicht [dao] benötigen kann, falls Daten mit der Datenbank ausgetauscht werden müssen. Die Anwendung erhält eine Antwort von der Schicht [métier].
    3. Anhand dieser Antwort wählt sie (3) die Ansicht (= die Antwort) aus, die an den Client gesendet werden soll, und stellt ihm (4) die benötigten Informationen (das Modell) zur Verfügung.
    4. Die Antwort wird an den Client gesendet (5)

    Hier handelt es sich um eine sogenannte MVC-Webarchitektur (Model – View – Controller):

    • [Application] ist der Controller. Er empfängt alle Anfragen des Clients.
    • [Saisies, Simulation, Simulations, ...] sind die Views. Ein View im Format .NET besteht aus Standardcode (ASP / HTML), der Komponenten enthält, die initialisiert werden müssen. Die Werte, die diesen Komponenten zugewiesen werden müssen, bilden das Modell der Ansicht.

    Wir werden hier das Muster (Design Pattern) MVC wie folgt implementieren:

    • Die Ansichten sind Komponenten vom Typ [View] innerhalb einer einzigen Seite vom Typ [Default.aspx]
    • Der Controller ist dann der Code [Default.aspx.cs] dieser einzelnen Seite.

    Nur einfache Anwendungen können diese Implementierung MVC unterstützen. Denn bei jeder Anfrage werden alle Komponenten der Seite [Default.aspx] instanziiert, also alle Ansichten. Beim Senden der Antwort wählt der Anwendungscode eine davon aus, indem er einfach die entsprechende Komponente [View] sichtbar macht und die anderen ausblendet. Verfügt die Anwendung über zahlreiche Ansichten, wird die Seite [Default.aspx] viele Komponenten enthalten, und die Kosten für deren Instanziierung können unerschwinglich werden. Zudem besteht die Gefahr, dass die Seite [Design] aufgrund der zu großen Anzahl an Ansichten unüberschaubar wird. Diese Art von Architektur eignet sich für Anwendungen mit wenigen Ansichten, die von einer einzigen Person entwickelt werden. Wenn sie eingesetzt werden kann, ermöglicht sie die sehr einfache Entwicklung einer MVC-Architektur. Genau das werden wir in dieser neuen Version betrachten.
