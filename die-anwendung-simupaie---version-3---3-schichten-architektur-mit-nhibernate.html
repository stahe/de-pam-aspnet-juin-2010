    7. Die Anwendung [SimuPaie] – Version 3 – 3-Schichten-Architektur mit NHibernate

    Empfohlene Lektüre: „C# 2008, Kapitel 4: 3-Schichten-Architekturen, Tests NUnit, Spring-Framework“.

    7.1. Allgemeine Architektur der Anwendung

    Die Anwendung [SimuPaie] wird nun die folgende dreischichtige Struktur aufweisen:

    • Die Schicht [1-dao] (DAO = Data Access Object) ist für den Datenzugriff zuständig.
    • Die Schicht [2-métier] ist für den fachlichen Aspekt der Anwendung, die Lohn- und Gehaltsabrechnung, zuständig.
    • Die Schicht [3-ui] (ui = User Interface) ist für die Darstellung der Daten gegenüber dem Benutzer und die Ausführung seiner Anfragen zuständig. Die Gesamtheit der Module, die diese Funktion gewährleisten, bezeichnen wir als [Application]. Sie ist der Ansprechpartner für den Benutzer.
    • Die drei Schichten werden durch die Verwendung von Schnittstellen unabhängig voneinander gestaltet.NET
    • Die Integration der verschiedenen Schichten erfolgt über Spring IoC

    Die Bearbeitung einer Kundenanfrage erfolgt in folgenden Schritten:

    1. Der Kunde sendet eine Anfrage an die Anwendung.
    2. Die Anwendung verarbeitet diese Anfrage. Dazu benötigt sie möglicherweise die Unterstützung der Schicht [métier], die ihrerseits die Schicht [dao] benötigen kann, falls Daten mit der Datenbank ausgetauscht werden müssen.
    3. Die Anwendung erhält eine Antwort von der Schicht [métier]. Entsprechend dieser Antwort sendet sie die entsprechende Ansicht (= die Antwort) an den Kunden.

    Nehmen wir als Beispiel die Berechnung des Gehalts einer Tagesmutter. Diese erfordert mehrere Schritte:

    1. Die Schicht [ui] muss den Benutzer fragen
      • die Identität der Person, für die das Gehalt berechnet werden soll
      • die Anzahl der von ihr gearbeiteten Tage
      • die Anzahl der gearbeiteten Stunden
    1. Dazu muss sie dem Benutzer die Liste der Personen (Nachname, Vorname, SS) aus der Tabelle [EMPLOYES] anzeigen, damit der Benutzer eine davon auswählen kann. Die Schicht [ui] nutzt den Pfad [2, 3, 4, 5, 6, 7], um diese Daten abzurufen. Die Operation [2] ist die Anfrage nach der Mitarbeiterliste, die Operation [7] die Antwort auf diese Anfrage. Anschließend kann die Schicht [ui] dem Benutzer die Mitarbeiterliste über [8] anzeigen.
    2. Der Benutzer übermittelt der Schicht [ui] die Anzahl der Arbeitstage sowie die Anzahl der geleisteten Arbeitsstunden. Dies entspricht dem oben genannten Vorgang [1]. In diesem Schritt interagiert der Benutzer ausschließlich mit der Schicht [ui]. Diese überprüft insbesondere die Gültigkeit der eingegebenen Daten. Anschließend fordert der Benutzer die Berechnung der Lohnabrechnung an.
    3. Die Schicht [ui] fordert die Fachschicht auf, diese Berechnung durchzuführen. Dazu übermittelt sie ihr die Daten, die sie vom Benutzer erhalten hat. Dies ist der Vorgang [2].
    4. Die Schicht [metier] benötigt bestimmte Informationen, um ihre Aufgabe erfolgreich auszuführen:
      • ausführlichere Informationen zur Person (Adresse, Index, …)
      • die mit ihrem Index verbundenen Zulagen
      • die Sätze der verschiedenen Sozialabgaben, die vom Bruttolohn abzuziehen sind

    Sie fordert diese Informationen von der Ebene [dao] über den Pfad [3, 4, 5, 6] an. [3] ist die ursprüngliche Anfrage und [6] die Antwort auf diese Anfrage.

    1. Da nun alle benötigten Daten vorliegen, berechnet die Ebene [metier] die Abrechnung der vom Benutzer ausgewählten Person.
    2. Die Schicht [metier] kann nun die in (d) gestellte Anfrage der Schicht [ui] beantworten. Dies ist der Pfad [7].
    3. Die Schicht [ui] formatiert diese Ergebnisse, um sie dem Benutzer in geeigneter Form darzustellen, und gibt sie anschließend aus. Dies ist der Pfad [8].
    4. Man kann sich vorstellen, dass diese Ergebnisse in einer Datei oder einer Datenbank gespeichert werden müssen. Dies kann automatisch erfolgen. In diesem Fall fordert die Schicht [metier] nach dem Vorgang (f) die Schicht [dao] auf, die Ergebnisse zu speichern. Dies erfolgt über den Pfad [3, 4, 5, 6]. Dies kann auch auf Anfrage des Benutzers erfolgen. In diesem Fall wird der Pfad [1-8] im Anfrage-Antwort-Zyklus verwendet.

    Aus dieser Beschreibung geht hervor, dass eine Schicht die Ressourcen der Schicht rechts von ihr nutzt, niemals jedoch die der Schicht links von ihr.

    Unsere erste Implementierung dieser 3-Schichten-Architektur wird eine Anwendung mit dem Namen ASP.NET sein, wobei

    • die Schichten [dao] und [metier] durch DLL implementiert werden
    • die Schicht [ui] durch das Webformular der Version 1 implementiert wird (siehe Abschnitt 4.2.1).

    Wir beginnen mit der Implementierung der Schicht [dao] mit dem Framework NHibernate.

    7.2.3. Die Klasse [PamException]

    Die Schicht [dao] ist dafür zuständig, Daten mit einer externen Quelle auszutauschen. Dieser Austausch kann fehlschlagen. Werden beispielsweise Informationen von einem Remote-Dienst im Internet angefordert, schlägt der Abruf bei einer beliebigen Netzwerkstörung fehl. Bei dieser Art von Fehlern ist es in Java üblich, eine Ausnahme auszulösen. Wenn die Ausnahme nicht vom Typ [RunTimeException] oder einem davon abgeleiteten Typ ist, muss in der Signatur der Methode angegeben werden, dass diese eine Ausnahme auslöst (throws). In .NET sind alle Ausnahmen unkontrolliert, c.a.d. entsprechen dem Java-Typ [RunTimeException]. Es ist daher nicht erforderlich, anzugeben, dass die Methoden vom Typ [GetAllIdentitesEmployes, GetEmploye, GetCotisations] eine Ausnahme auslösen können.

    Es ist jedoch sinnvoll, die Ausnahmen voneinander unterscheiden zu können, da ihre Behandlung unterschiedlich sein kann. So lässt sich der Code zur Behandlung verschiedener Ausnahmetypen wie folgt schreiben:

    try{
    ... code pouvant générer divers types d'exceptions
}catch (Exception1 ex1){
...on gère un type d'exceptions
}catch (Exception2 ex2){
...on gère un autre type d'exceptions
}finally{
...
}

    Wir erstellen also einen Ausnahmetyp für die Schicht [dao] unserer Anwendung. Es handelt sich um den folgenden Typ [PamException]:

    
using System;
namespace Pam.Dao.Entites {

    public class PamException : Exception {

        // Fehlercode 
        public int Code { get; set; }

        // Konstruktoren 
        public PamException() {
        }

        public PamException(int Code)
            : base() {
            this.Code = Code;
        }

        public PamException(string message, int Code)
            : base(message) {
            this.Code = Code;
        }

        public PamException(string message, Exception ex, int Code)
            : base(message, ex) {
            this.Code = Code;
        }
    }
}
    • Zeile 2: Die Klasse gehört zum Namensraum [Pam.Dao.Entites]
    • Zeile 4: Die Klasse leitet sich von der Klasse [Exception] ab
    • Zeile 7: Sie verfügt über eine öffentliche Eigenschaft [Code], bei der es sich um einen Fehlercode handelt
    • Wir werden in unserer Schicht [dao] zwei Arten von Konstruktoren verwenden:
      • den in den Zeilen 18–21, den wir wie unten gezeigt verwenden können: 
    throw new PamException("Problème d'accès aux données",5);
    • (Fortsetzung)
      • oder den in den Zeilen 23–26, der dazu dient, eine bereits aufgetretene Ausnahme weiterzuleiten, indem er in eine Ausnahme vom Typ [PamException] gekapselt wird: 
    try{
....
}catch (IOException ex){
     // Die Ausnahme wird gekapselt
    throw new PamException("Problème d'accès aux données",ex,10);
}

    Diese zweite Methode hat den Vorteil, dass die Informationen, die die erste Ausnahme enthalten kann, nicht verloren gehen.

    7.2.5. Die Schnittstelle [IPamDao] der Schicht [dao]

    Kommen wir zurück zur Architektur unserer Anwendung:

    In einfachen Fällen kann man von der Schicht [metier] ausgehen, um die Schnittstellen der Anwendung zu ermitteln. Für den Betrieb benötigt sie Daten:

    • die bereits in Dateien, Datenbanken oder über das Netzwerk verfügbar sind. Diese werden von der Schicht [dao] bereitgestellt.
    • noch nicht verfügbar sind. In diesem Fall werden sie von der Schicht [ui] bereitgestellt, die sie vom Benutzer der Anwendung erhält.

    Welche Schnittstelle muss die Schicht [dao] der Schicht [metier] bereitstellen? Welche Interaktionen sind zwischen diesen beiden Schichten möglich? Die Schicht [dao] muss der Schicht [metier] folgende Daten bereitstellen:

    • die Liste der Tagesmütter, damit der Benutzer eine bestimmte Tagesmutter auswählen kann
    • vollständige Informationen über die ausgewählte Person (Adresse, Index, …)
    • die mit dem Index der Person verbundenen Vergütungen
    • die Sätze der verschiedenen Sozialbeiträge

    Diese Informationen liegen bereits vor der Lohnabrechnung vor und können daher gespeichert werden. In der Richtung [metier] -> [dao] kann die Schicht [metier] die Schicht [dao] auffordern, das Ergebnis der Lohnabrechnung zu speichern. Dies werden wir hier jedoch nicht tun.

    Mit diesen Informationen könnte man eine erste Definition der Schnittstelle der Schicht [dao] versuchen:

    
using Pam.Dao.Entites;

namespace Pam.Dao.Service {
    public interface IPamDao {
        // Liste aller Mitarbeiteridentitäten 
        Employe[] GetAllIdentitesEmployes();
        // ein bestimmter Mitarbeiter mit seinen Zulagen 
        Employe GetEmploye(string ss);
        // Liste aller Beiträge 
        Cotisations GetCotisations();
    }
}
    • Zeile 1: Der Namensraum der Entitäten der Schicht [dao] wird importiert.
    • Zeile 3: Die Schicht [dao] befindet sich im Namensraum [Pam.Dao.Service]. Elemente des Namensraums [Pam.Dao.Entites] können mehrfach angelegt werden. Elemente des Namensraums [Pam.Dao.Service] werden nur einmal angelegt (Singleton). Dies war der Grund für die Wahl der Namen der Namensräume.
    • Zeile 4: Die Schnittstelle heißt [IPamDao]. Sie definiert drei Methoden:
      • Zeile 6: [GetAllIdentitesEmployes] gibt ein Array von Objekten des Typs [Employe] zurück, das die Liste der Tagesmütter in vereinfachter Form darstellt (Nachname, Vorname, SS).
      • Zeile 8: [GetEmploye] gibt ein Objekt vom Typ [Employe] zurück: den Mitarbeiter, dessen Sozialversicherungsnummer als Parameter an die Methode übergeben wurde, zusammen mit den seinem Index zugeordneten Zulagen.
      • Zeile 10: [GetCotisations] gibt das Objekt [Cotisations] zurück, das die Sätze der verschiedenen Sozialabgaben enthält, die vom Bruttolohn abzuziehen sind.
